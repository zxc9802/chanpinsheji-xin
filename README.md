# 青匣 · Verdant Atelier —— AI 包装设计智能体

**上传一份产品文档，点「开始设计并出图」，直接出图**——上传本身不会开始出图，需要点右下角的按钮；设计简报已内置在流程里自动生成，无需手动确认；想调整时，点渲染区的「设计简报 · 自定义」修改，再一键重新生成。

**先看方向，再出整套**：JEV 会从参考库里挑出最多 3 个**不同品牌**的参考，每个方向各写一份设计简报，并同时出一张外包装正视图预览（约 1 分钟）。你选定一个，其余视图（默认 5 张）再基于它补全，没被选中的方向不会再花钱出图。JEV 只给出一个明确答案、或没有第二个合适的品牌时，自动退回单方向的直接出图。

自动产出：

- **设计简报**（内置，可随时打开自定义）：产品提炼、设计概念、色彩系统、字体与纹样、结构与印刷工艺、每个面的印刷文案（全部可在线修改，改完点「重新生成」按新简报重绘）
  - 背面的成分表、使用方法、生产商、执行标准等文档没写的版面信息，会按品类惯例编造补全，保证每个面像定稿包装，不会印「待确认」；编造的部分会记在简报数据的 `referenceExplanation.unknown` 里（页面不展示），投产前替换为真实信息（功效、认证、专利、奖项仍不编造）
- **外包装三视图**：正视图 / 侧视图 / 背视图
- **内包装三视图**：正视图 / 侧视图 / 背视图
- **主视觉全家福**（可选，默认关闭）：16:9 场景大片，在「高级选项」里开启
- **电商主图 + 详情图**：在第二页「交付提案」里点「生成主图 + 详情图」，用这套包装里的某几张图（或自己上传的产品图）一键生成，见下文
- **交付物**：打包下载全部高清图 + 设计简报 + 电商图（ZIP）
- **设计参考**：JEV 匹配研究库中的具体产品，作为设计与渲染依据；每个方向的预览、三视图、主视觉和单张重绘均传入该方向对应的参考图片。

## 快速开始

**方式一：双击 `启动.command`**（macOS），首次会自动安装依赖并打开浏览器。

**方式二：命令行**

```bash
npm install
npm start
```

然后打开 <http://localhost:3789>

已有产品图时，点击首页「上传产品图，生成套图」：拖入或点击上传同一件产品的 1–4 张 PNG / JPG / WebP 图片，勾选主图、详情图或同时勾选两者，即可直接生成套图，无需先做包装设计。选择详情图时可选 10 屏或 16 屏结构。产品介绍选填，可输入文字并上传一份文档（最大 25 MB，支持 PDF、Word/DOCX、PPT/PPTX、Excel/XLSX、MD/Markdown、TXT、CSV、JSON、HTML）。文档文字与补充说明一起参与产品识别和套图规划，补充说明优先；解析内容随项目保存，重新规划时可沿用，重新选择产品图时可保留、移除或替换文档。旧版 DOC/PPT/XLS 请先另存为 DOCX/PPTX/XLSX 或 PDF；扫描 PDF 需要先做文字识别。结果自动保存到作品集，支持单张重绘、ZIP 下载与合成详情长图。

> 需要 Node.js 20.16+（20.x），或 22.3+；不支持 Node.js 21，与 PDF 解析依赖的要求保持一致。

## 模型配置

密钥保存在项目根目录的 `.env` 中，只在服务端使用，不会下发到浏览器：

| 变量 | 说明 |
| --- | --- |
| `FAL_KEY` | 图片模型密钥（fal.ai） |
| `IMAGE_MODEL` | 默认 `openai/gpt-image-2.5/sunburst/edit` |
| `LLM_API_KEY` | 文案解析模型密钥 |
| `LLM_BASE_URL` | 默认 `https://api.openlux.ai/v1/chat/completions` |
| `LLM_MODEL` | 首选文案模型，默认 `gpt-6-luna` |
| `LLM_FALLBACK_MODEL` | 备用文案模型，默认 `deepseek-v4.1-flash`，共用上述接口与密钥 |
| `PORT` | 默认 `3789` |
| `JEV_API_KEY` | 参考选择模型密钥，仅在服务端使用 |
| `JEV_BASE_URL` | `https://api.openlux.ai/v1/systemone` |
| `JEV_MODEL` | `jev-1.13.0` |
| `REFERENCE_LIBRARY_ROOT` | 可选：研究库根目录，默认读取旁边「产品设计」项目的 `research/beauty-design-2026-09-28` |
| `ECOMMERCE_LIBRARY_ROOT` | 可选：电商设计参考库根目录，默认 `research/ecommerce-design-2026-09-30`（含 `agent-library/catalog.json`） |

文案解析先调用 `gpt-6-luna`，失败后重试 3 次（最多 4 次调用），仍失败再自动切换 `deepseek-v4.1-flash`。备用模型保留原有的一次重试。网络错误、超时、接口报错、空输出或无法解析的 JSON 均计为失败；请求使用流式输出（网关会切断超过约 60 秒没有任何输出的连接，完整简报常需 2–3 分钟）；首字等待超过 150 秒、输出中途连续 60 秒没有新内容、或单次超过 300 秒才算超时（网关排队时第一个字可能要等一两分钟）。被截断或中途断开的输出会直接报出原因，并计入重试。服务日志记录实际调用模型、尝试次数与耗时，不记录密钥或文档正文。

## 工作原理

```
上传文档（或粘贴文字）→ 点「开始设计并出图」才开始
产品文档 → 纯文本 → JEV 判断（一次调用，给出每个候选的概率）
                     │  按概率取前 3 个不同品牌（概率只排序、不设门槛）
        ┌────────────┼────────────┐
        ▼            ▼            ▼
     方向 A        方向 B        方向 C      各自：GPT 结合该参考的设计档案写简报（失败转 DeepSeek）
        │            │            │
        ▼            ▼            ▼
   外包装正视图  外包装正视图  外包装正视图   3 张并行出图，约 1 分钟
        └────────────┼────────────┘
                     ▼
                 你选一个方向  ← 也可以「重画」某个方向，选定后仍可改用别的方向
                     │
  Stage I   外包装正视图 = 选中方向的预览（直接沿用，不再重画）
  Stage II  外包装侧视 · 外包装背视 · 内包装正视  ← 以正视图为一致性参考
  Stage III 内包装侧视 · 内包装背视（· 主视觉，可选） ← 以外包装正视 + 内包装正视为参考
```

三视图分阶段生成、逐级引用前一阶段成图，保证不同角度是**同一件包装**。除主视觉外，每张图画面里只有一个对象：外包装视图只画这一面的外盒，内包装视图只画内装主体本身，不会把外盒、瓶身或多视角拼在一起（提示词里明确排除，内包装视图也不会收到外盒结构和外盒参考描述；用外包装图作一致性参考时，只取品牌、颜色与图形）。选定方向后，该方向的简报和参考成为项目的设计，之后的「设计简报」修改、单张重绘、全部重绘都以它为准。

研究库与原 BlingPack 共用一份目录，不依赖另一个智能体的服务进程；更新目录中的档案后重启青匣即可载入。首次召回最多 8 个案例，同品类与相关品类优先；未选中时扩大到 16 个。平行方向取自**同一次** JEV 判断的概率排序，不是关键词或标签，也不会再额外调用 JEV；同一品牌只保留概率最高的一个，让三个方向真正不同。方向的参考图要能真正用上：库里雅诗兰黛、娇兰、兰蔻、祖玛珑的参考图是 AVIF，会先用 macOS 自带的 `sips`（其次 `ffmpeg`）转成 PNG 并缓存到 `data/cache/`；超过 1.5 MB 的大图缩到长边 1600 px 再上传（4–5 MB 的 PNG 在慢网络上会让提交请求超时）；参考图仍不可用的候选会被跳过，由下一个品牌顶上；某个方向在写简报等环节出任何错，同样换下一个品牌顶上（整轮最多换 3 次，避免服务整体故障时无限重试；换掉的品牌不会再出现）。概率不设门槛：JEV 对首选很确定时，其余候选的概率都会接近 0，但它们仍是召回阶段选出的同类参考，照样作为另外两个方向。只有产品资料也可匹配，风格、容器和外盒由智能体建议。明确硬性冲突仍会拒绝匹配，JEV 服务失败不会静默换模型。

匹配后将图片原文件及 SHA-256 保存到当前项目，作为独立于用户 Logo 和已生成视图的参考来源。真实图片内容通过 fal 的 `image_urls` 传入，素材缺失或变更时不会悄悄改用空白图。每张图及历史版本的 `referenceInputs` 记录实际使用的文件和角色。缺少已核单品外盒图时，会明确创建配套新设计。历史项目可在「设计简报」里点击「重新构思」重新挑选方向（会立即开始出预览，并取代当前这套图）。

- 支持的文档：PDF、DOCX、PPTX、XLSX、Markdown、TXT、HTML、CSV/JSON
- 参考图：最多 4 张产品照片或 Logo（PNG / JPG / WEBP）
- 渲染精度：快速（medium）/ 精致（high，默认）/ 极致（xhigh）
- 每张图都可以单独「重绘」并附带修改意见，旧版本会保留，可在大图里切换

## 电商主图 + 详情图

第二页交付栏的「生成主图 + 详情图」（替换了原来的提案板导出）。流程与包装设计的参考方式相同，但**参考库换成电商设计库**：

1. **选产品图**：从这套包装已出的视图里选，或上传自己的图（PNG / JPG / WebP，合计最多 4 张，应是**同一件产品**的不同角度）。再选生成内容：仅主图 / 仅详情图 / 两者。
2. **选择详情结构**：标准详情固定 10 屏，证据链详情固定 16 屏。替换旧的 5–12 屏自适应规划；资料或参考图不足也不删屏。
3. **直接规划与生成**：JEV 判断品类与形态 → 选择参考库视觉系统 → 按固定结构分配资料 → 为各屏挑参考 → 首图定调后并行出图。主图固定 5 张（1:1），白底图独立；详情图使用 `1152×2048`（9:16）。
4. **保存和调整**：结构选择随项目保存；设计简报支持改屏名、标题、辅助文字和构图，单屏重绘沿用本屏模块提示词。ZIP 包含当前图片和结构说明。旧方案可继续查看和下载；再次生成详情时需选择新结构。

### 固定主图、详情结构与提示词来源

- **5 张主图**：白底图 → 首图 → 次图-成分 → 次图-效果 → 次图-使用场景。白底仅保留原产品并换纯白背景；其余分别使用产品大图、成分微距、效果/体验、真实使用场景，避免套用同一构图。资料和参考不足也保留 5 张，减少文案并记录缺失证据。
- **10 屏**：详情首图 → 品牌与资质 → 研发实力 → 痛点场景 → 效果对比 → 竞品对比 → 产品大图强化 → 成分总览 → 使用方法 → 产品信息。
- **16 屏**：首屏爆点 → 痛点放大 → 产品解决方案 → 差评与竞品对比 → 真人实测引入 → 效果验证 → 研发体系 → 核心成分一机制 → 核心成分一证明 → 核心成分二机制 → 辅助功效机制 → 辅助功效验证 → 真人反馈 → 质地肤感 → 品牌感与情绪价值 → 使用方法。

提示词来自 [dianputu](https://github.com/zxc9802/dianputu/tree/42e2de6502ab9bbe40c806237f96735019318239) 的 `current` 默认提示词分支。`lib/dianputu-main-prompts.json` 保存 5 个主图模块，`lib/dianputu-detail-prompts.json` 保存 26 个详情模块及来源版本；`lib/commerce-main.js` 和 `lib/commerce-detail.js` 填入本项目产品资料、每屏文案和参考图信息。`lib/commerce-spec.js` 保留旧主图方案重绘的规格以及共用文案校验。

保留原版的模块任务、产品露出策略、构图、文字边界、视觉减法和参考图优先级；接入本项目的参考库、首图定调、图片服务与历史版本。明确适配：不补造原版默认的 89% 等示例数据，0 添加只使用有资料支持的宣称；主图最多呈现 2 个已确认成分，没有真实效果数据时使用体验标签，不画测量图表或实测对比。缺失证据记录在简报中，图片不显示内部资料缺失提示。适配差异保留在快照来源信息中。已保存的旧主图方案继续按原结构查看和重绘，重新生成套图时采用新的固定 5 张结构。

可用 `python3 scripts/import-dianputu-prompts.py /path/to/dianputu` 从指定 commit 重新提取提示词；应用运行无需 Python。参考图片仍保存为带 SHA-256 的项目快照。单屏没有对应参考时，按模块提示词和整套风格生成，不删屏。

### 一键合成详情长图

详情图全部出完、没有在重绘的时候，结果区右上角的「合成详情长图」会亮起（还差几屏会在按钮提示里写出来）。点一下：

- 按详情页的先后顺序把每一屏**无缝**拼成一张竖长图，宽度统一为 750px（淘宝 / 天猫详情页的标准宽度），高度由屏数决定（9:16 分图每屏约 1333px，10 屏约 13330px，16 屏约 21328px）；
- 用的是每一屏**当前选定的版本**，想换哪一屏，先重绘或在历史版本里选好再合成；
- 弹窗里可以上下滚动预览，再下载 JPG（体积小，适合直接上传）或 PNG（无损）；
- 在浏览器里合成，不经过服务器，也不产生费用。主图是单独上传的 1:1 图片，不放进长图。

```

lib/pipeline.js      三阶段渲染流水线 + 平行方向的正视图预览
lib/jev.js           JEV System One 判断与结果校验
lib/references.js    共用参考库的召回、匹配和设计模板
lib/commerce.js      电商图：JEV 选视觉系统与每屏参考，规划主图 / 详情图的每一屏
lib/commerce-spec.js 旧主图规格与共用文案校验
lib/commerce-main.js 固定 5 张主图规划与提示词填充
lib/dianputu-main-prompts.json 原仓库 5 个主图模块提示词快照
lib/commerce-detail.js 固定 10 / 16 屏规划与提示词填充
lib/dianputu-detail-prompts.json 原仓库 26 个详情模块提示词快照
lib/commerce-render.js 电商图：首图定调、其余并行出图、单屏重绘
lib/store.js         项目持久化（data/projects/<id>/）
public/              前端页面（原生 HTML / CSS / JS，无需构建）
public/js/commerce.js 电商图的入口弹窗、结果区与设计简报
public/js/longimage.js 详情长图：把详情屏按顺序拼成一张竖长图（浏览器里合成）
public/js/board.js   提案板排版（已不在页面里使用，保留代码）
data/projects/       所有作品：project.json + 参考图 + 渲染图
```

接入验证：运行 `node --test tests/*.test.mjs`。测试覆盖产品资料匹配、扩大候选、真实图片输入、单张重绘与参考记录；平行方向的测试覆盖 JEV 概率取前几名、去重品牌、只出正视图、并行出图、选定后只补其余视图、单个方向失败后重试；电商图测试覆盖固定 5 张主图与 10/16 屏详情的顺序、完整性校验、缺少参考不删屏、文案事实边界、不同模块构图、白底图独立、JEV 挑系统与参考、首图先出其余并行、单屏重绘与失败恢复、上传选择范围、保存及 ZIP 导出；全部使用模拟的 JEV / 文案 / 生图接口，不产生费用，项目数据写在临时目录里。
