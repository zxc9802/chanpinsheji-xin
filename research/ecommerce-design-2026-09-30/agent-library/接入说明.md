# 电商主图与详情图参考库接入

这是一份研究数据接口，不是已上线功能。版本 1.0，采集于 2026-09-30。沿用包装参考库的“程序筛选 → 小候选集判断 → 实际参考图片进入生成”策略。

## 文件

| 文件 | 用途 |
| --- | --- |
| `catalog.json` | 完整商品、热度、风格、原图、主图任务、详情内容屏 |
| `candidates.json` | 已去掉 `excluded` 的轻量候选；`conditional` 仍需条件筛选 |
| `generation-recipes.json` | 每品类的主图/详情编排建议，明确属于设计建议 |
| `screens.csv` | 人工复核用的 489 条分屏记录 |
| `../assets/<id>/` | 真实采集图片转为 JPG 的研究副本；不能只把路径字符串发给图像模型 |
| `../evidence/` | 商品图来源、尺寸、顺序与热度摘录；搜索卡可回溯原文 |

**路径基准**：所有 JSON 的 `path` / `reference_images` 均相对 `research/ecommerce-design-2026-09-30/`，即 `catalog.json` 所在目录的上一级。先据此解析绝对路径，再读图片字节上传到生成服务。

## 输入与事实

建议输入对象：

```json
{
  "input_mode": "single_image | generated_packaging_image | same_product_multiview",
  "product_images": [{"path": "用户素材绝对路径", "view": "front", "sku_id": "同款标识"}],
  "category": "沐浴露",
  "form": "大泵瓶",
  "confirmed_facts": {
    "product_name": "用户确认的名称",
    "confirmed_benefits": [],
    "confirmed_ingredients_or_scent": [],
    "verified_specs_and_label": {},
    "confirmed_instructions": []
  },
  "additional_assets": {
    "texture_reference": [],
    "matching_multiview_or_structure_assets": [],
    "product_specific_evidence": [],
    "verified_shades_and_swatch_assets": [],
    "product_specific_makeup_assets": []
  }
}
```

包装生成图只能证明当前想要的外观。图中的自动生成文案不自动转为已确认的功效、认证或成分。多角度图先核对同 SKU、同版标签、容量与瓶盖结构，不拼成混合产品。

## 筛选顺序

1. 从 `products` 依据品类与包装形态筛选。优先同品类；跨品类仅在结构相符时借构图，记录原因，不借事实。
2. 确定本次有哪些内容任务。没有配方/质地/用法/报告就跳过相应屏。
3. 排除 `eligibility=excluded`。`conditional` 必须逐项满足 `required_inputs`。单图输入不选需要额外视角的结构任务。
4. `ready` 表示布局可用，**不表示来源图片可以不改地生成或发布**。仍需锁定用户产品，删除源图的品牌、数字、价格、人物和报告。
5. 同一任务选一个主视觉系统；根据形态、配色适配、信息密度和目标内容角色，保留约 3—5 个候选给 JEV/判断模型。热度仅作已入库的依据，不把最大销量当最高设计适配分。
6. 跨切片的内容屏按 `source_asset_ids` 有序读取。`source_contains_neighbor_section=true` 时需人工或视觉模型确认对应区域后裁切；不能默认整张都是当前屏。未处理的跨屏素材只用于整体阅读，不直接作为精确局部生成参考。
7. 判断结果返回具体 `reference_id`、素材 ID、选择理由与待满足条件。把选中的实际图片与用户图片分别作为 style reference / identity reference 传入生成服务。

推荐判断输出：

```json
{
  "visual_system": "safeguard",
  "screens": [{
    "slot": "main_01",
    "role": "hero",
    "reference_id": "safeguard-main-screen-04",
    "source_asset_ids": ["safeguard-hero-04"],
    "borrow": ["主体比例", "前景与背景关系", "文字留白位置"],
    "identity_images": ["用户产品正面图"],
    "allowed_facts": ["用户已确认的产品名"],
    "remove_from_reference": ["舒肤佳标识", "来源包装", "未确认的石榴元素和香调", "来源功效文案"]
  }]
}
```

不要只输出“清新高级”之类提示词。上面只是数据示例，未调用 JEV，也不表明本功能已经接入。

## 生成与验收

用户产品图控制瓶型、比例、泵头、标签、色彩；库图控制布局、信息层级和背景关系。单一视角只生成该视角可支持的外观。未知背面、内胆、膏体和套装件数不能从风格图中补造。

主图与详情统一视觉系统，按已确认内容缩短或增加屏数。无资料时允许仅输出产品图与简单场景。效果图、实验曲线、测试报告、明星、榜单“第一”和促销权益不凭空补齐。来源热度不能变成用户产品的销量文案。

后续验收应核查：产品身份一致；每一屏有明确任务；事实能回到用户资料；参考图片实际进入生成请求；缺资料屏确实被跳过；输出尺寸与目标平台版位要求另行验证。当前仅验证研究数据和浏览页，不代替真实生图端到端验收。

## 第二批新增

现有 20 个商品、19 类产品、541 张图片、303 条条件化候选。新增软管、喷雾罐、礼盒、香水瓶、滴管瓶及盘状彩妆。色号与妆效分别使用 `shade` / `makeup`；不能把包装图中的颜色作为真实试色。

`generation-recipes.json` 为逐商品编排建议，不强制每款都有产品、成分、教程等全部角色；例如眼影案例从选型与妆效进入，香水以产品、香调和礼赠为主。原页没有出现的教程不会补写成观察结果。部分来源为动画，JPG 是静态预览帧；本库不声称分析了全部动画过程。
